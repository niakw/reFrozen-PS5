# Synthetic Win64 translated-chain PS5 ELF

Status: **CI-link experiment; hardware execution required.**

This probe is the first PS5 artifact intended to combine the two previously
separate proof tracks:

1. PS5 exact-address/direct-memory guest mapping.
2. Static translation of a Windows x86-64 function to native C.

It contains **no Warcraft III code or data**.

## Synthetic guest

The public fixture generated by `scripts/ps5/synthetic_pe64_memory.py`
contains one Win64 function at guest address `0x140001000`:

```text
load dword [0x140002000]
+ 1
store dword [0x140002000]
return
```

The PE's initial `.data` value is `41`. The pinned Win64 translator turns
that function into C (`F_140001000`). The generated C is then cross-compiled
with the PS5 Payload SDK and linked into the native probe ELF.

## Hardware execution path

```text
MapGuestImagePs5(0x140000000, 0x5000)
  -> exact PS5 VA reservation
  -> direct-memory backing (rounded to native granularity)
  -> MaterializePeImage(public synthetic PE)
  -> verify guest .data == 41
  -> F_140001000(CPU*)
  -> verify guest .data == 42 + CPU state
  -> ReleaseGuestImagePs5
```

The guest PE mapping remains data-only/non-executable. The PS5 executes the
native code generated from the guest function; it never executes the mapped
x86-64 PE bytes.

Expected success log:

```text
REFROZEN_PS5_WIN64_CHAIN pass=1 base=140000000 logical=5000 stored=42 rax=2a ...
```

## Reproducible build inputs

- PS5 Payload SDK v0.42, pinned by SHA-256 in CI.
- NightSightProductions/Recomp-Framework commit
  `63742ed02e039b292bbf341a33b3bb8c73457fea` (MIT), used only for the
  synthetic Win64 translation proof.
- Public synthetic PE generated in CI.
- reFrozen PS5 mapping/materialization code from this repository.

The CI must reject unsupported translated instructions, unexpected desktop ELF
dependencies, accidental `__atomic_*` runtime dependencies and runner-path
leakage before uploading the artifact.

## Qualification boundary

A green workflow proves that this chain **links** for the PS5 ABI. It does not
prove that firmware accepts the exact `0x140000000` mapping or that the
translated function executes on hardware. Those two facts require the PS5 log.

Only after the synthetic chain passes on the console should a privately owned
Warcraft module be analyzed/recompiled. Generated C from proprietary game
binaries must remain outside this public repository and its Actions artifacts.
